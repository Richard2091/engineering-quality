# 后端和接口项目类型规则

## 适用条件

当项目包含网络服务、接口、常驻进程、后台任务、数据库访问或外部系统集成时启用。本文件可与数据与模型、交付和运维、基础设施规则组合；纯前端或纯静态库不适用。

## 项目类型画像

实施或审查前记录：

- 入口：服务启动、路由、中间件、控制器、任务调度和消费入口。
- 核心资产：接口契约、应用服务、领域规则、数据访问、任务状态和配置。
- 主要依赖：数据库、缓存、队列、模型服务、第三方接口、身份系统和文件存储。
- 关键风险：越权、数据损坏、重复执行、并发冲突、资源耗尽、静默失败和不可恢复。
- 生命周期：开发、联调、预发布、生产、迁移、重构或维护。

## 需求与设计

### 需求澄清

实施前明确目标用户、业务场景、非目标范围、接口输入输出、成功标准、错误语义、权限条件、性能目标和兼容要求。关键歧义、外部依赖、数据口径和高影响决策必须先确认，不能带着关键歧义直接编码。

### 现状调研

读取仓库规则、服务入口、路由、中间件、公共异常、鉴权、日志、数据访问、任务、配置、接口文档和已有测试。优先复用项目已有能力，避免重复实现认证、分页、事务、重试、日志和基础设施。

### 模块边界

- 控制器/路由负责协议适配和请求编排。
- 应用服务负责用例流程和事务协调。
- 领域或业务模块负责可测试的业务规则。
- 数据访问层负责查询、持久化和迁移适配。
- 外部适配层负责第三方调用、超时、重试、错误转换和资源释放。
- 任务调度和消费逻辑负责状态推进、幂等、重试和死信/人工处理。

避免控制器直接堆叠业务规则、数据库细节和外部调用；避免服务层成为无边界的万能类。

### 接口与失败策略

设计路径、方法、参数、响应、错误码、分页、排序、过滤、版本、幂等和废弃策略。明确参数错误、鉴权失败、资源不存在、重复请求、上游失败、超时、客户端断开、数据库锁冲突和部分成功的处理。

## 实施规范

### 阶段化流程

1. 需求澄清并形成接口/验收草案。
2. 调研现状并确认可复用能力和影响范围。
3. 设计模块、接口、数据、权限、并发、事务、失败和兼容策略。
4. 分阶段实施，每阶段独立测试和审查。
5. 执行接口、集成、构建和必要的运行验证。
6. 输出接口文档、迁移说明、测试记录、运行手册和变更总结。

简单内部逻辑可以直接实施；涉及公共接口、数据迁移、权限、并发或多模块变更时必须分阶段。每阶段都应有方案、实现、测试、审查、风险和完成标准，前一阶段未通过不得默认进入下一阶段。

### 服务生命周期

- 启动阶段校验必需配置、依赖连接和版本；失败要明确退出原因。
- 提供与实际路径、端口和配置一致的健康/就绪检查。
- 优雅关闭时停止接收新请求，等待或取消任务并释放连接。
- 后台线程、定时任务和消费者异常必须可观察，不能静默退出。
- 为任务状态、重试次数、超时和最终失败保留可定位信息。

### 请求、外部调用与资源

- 校验类型、长度、范围、格式、请求体大小和分页上限。
- 认证与授权分离；资源级权限不能只依靠路由级角色判断。
- 外部调用设置连接、读取和总超时；重试只用于明确可重试错误并采用退避。
- 为高成本接口、批量接口和后台任务设置限流、并发上限、背压和资源配额。
- 写操作设计幂等键、唯一约束、重复检测和补偿策略。
- 错误信息脱敏，日志包含请求关联标识、业务标识和必要上下文。

### 数据库、事务与迁移

- 明确事务边界、提交/回滚、锁超时、连接池、查询范围、索引和分页。
- 迁移脚本作为正式交付物，支持多环境、幂等执行和失败定位。
- 评估固定 ID 冲突、旧版本兼容、数据回填、分批执行、前向修复和回滚/补偿。
- 迁移前确认备份，迁移后验证结构、数据数量、关键约束和应用兼容性。
- 无法执行恢复演练时标记未验证，不把“存在备份文件”当作恢复通过。

### 代码与注释

涉及业务逻辑、流程控制、数据处理、状态变更和接口编排的方法，上方添加中文 Javadoc，按需写明 `@param`、`@return`；方法内部用中文步骤注释说明关键过程。简单实体、枚举和 getter/setter 不强制添加。

## 测试规范

- 单元测试：业务规则、校验、错误转换、幂等和状态转换。
- 集成测试：数据库、事务、缓存、队列、文件和外部适配器。
- 接口/契约测试：成功、参数错误、鉴权失败、越权、资源不存在、重复、超时、上游失败和兼容性。
- 并发和资源测试：重复请求、锁冲突、限流、背压、任务重试和连接耗尽。
- 启动与恢复测试：配置缺失、健康检查、优雅关闭、任务恢复、迁移失败和回滚/补偿。

默认优先使用模拟和本地测试。真实接口、真实数据库、测试服务器或生产环境验证必须单独授权，并记录环境、请求、返回、数据状态和最终结果。测试失败必须定位、修复、重新验证，不得跳过直接相关失败项。

## 交付与运维

交付前按变更类型判断是否需要：接口文档、数据字典、迁移脚本、回滚/补偿说明、配置说明、测试报告、部署说明、运行手册和变更记录。

检查构建、静态检查、依赖、启动、健康检查、日志、指标、告警、任务最终状态和发布后核心接口。分支、工作树、合并请求、部署和清理仅在仓库或用户要求时启用；目标分支和部署目标不明确时先确认。

## 典型问题和反模式

- 控制器直接处理全部业务、事务、数据库和外部调用。
- 没有统一错误模型，异常堆栈或敏感数据返回给客户端。
- 只做角色校验，不做资源级授权。
- 无限重试、无超时、无并发上限，导致级联故障。
- 写操作没有幂等和唯一约束，重复请求产生重复数据。
- 迁移不可重复执行，没有回滚、补偿或旧版本兼容方案。
- 后台任务失败后静默停止，接口仍显示服务正常。
- 只验证成功响应，不验证数据状态和异步最终结果。

## 验收证据

检查路由、中间件、控制器、应用服务、业务模块、数据访问、迁移、任务调度、配置、接口文档、测试、健康探针、日志指标和部署清单。

保留实际命令、执行环境、请求或输入、响应或输出、数据库/任务状态、测试结论、未验证原因、发布方式、回滚方式和剩余风险。
