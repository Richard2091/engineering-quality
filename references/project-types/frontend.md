# 前端项目类型规则

## 适用条件

当项目包含浏览器页面、桌面网页、前端资源、组件库或面向用户的交互界面时启用。本文件可与后端、数据与模型、交付和运维规则组合使用；纯接口、纯数据处理或没有用户界面的任务不适用。

### 何时启用专项检查

- 页面、路由、组件、状态、请求和样式发生变化时，启用结构与交互规则。
- 涉及用户输入、令牌、富文本、第三方脚本或权限时，启用安全规则。
- 涉及构建、包体积、部署和浏览器支持时，启用性能与交付规则。
- 只是修改文案或静态资源时，仍需根据影响范围决定是否执行构建和视觉验证。

## 项目类型画像

实施或审查前记录：

- 入口：应用入口、路由、页面、组件、状态管理和请求封装位置。
- 核心资产：页面、可复用组件、主题样式、接口类型、静态资源和构建产物。
- 主要依赖：浏览器能力、后端接口、身份认证、第三方脚本、图表/编辑器/地图等组件。
- 关键风险：权限绕过、敏感信息泄露、跨站脚本、状态不一致、重复提交、性能退化和兼容性问题。
- 生命周期：原型、迭代开发、预发布、生产维护或组件库发布。

## 需求与设计

### 目标和边界

- 明确用户、页面入口、核心操作、成功状态、异常状态和非目标行为。
- 明确接口输入输出、权限条件、字段展示口径、分页排序和时间时区。
- 明确浏览器、设备、分辨率、网络条件和兼容范围；不确定内容标记待确认。

### 模块边界

- 页面负责布局和流程编排，组件负责稳定的展示和交互，状态层负责状态管理，请求层负责接口访问，业务逻辑应保持可测试。
- 服务端状态、页面状态、表单状态和展示状态分开管理，避免无理由扩大为全局状态。
- 公共组件只抽取稳定且有多个使用场景的能力；一次性页面逻辑不应过早泛化。
- 路由、权限和数据加载边界要清晰，避免页面组件直接堆叠请求、转换、校验和提交逻辑。

### 状态与失败策略

设计并实现与风险相关的加载、空数据、错误、无权限、过期、重试、取消、重复提交、离线和部分成功状态。

## 实施规范

### 页面级实施流程

1. 确认页面入口、用户目标、接口契约和验收场景。
2. 调研现有页面、组件、状态、请求封装和样式复用能力。
3. 设计页面、组件、状态和请求层边界，再确定文件位置。
4. 实现主流程和失败状态，同时补充类型、错误处理、日志或前端异常采集。
5. 补充组件/接口模拟/浏览器测试，并执行构建和兼容性检查。
6. 进行独立复审，确认交互、权限、安全和文件拆分没有遗漏。

简单文案或样式任务可以直接实施；跨页面、跨接口、涉及权限或状态迁移的任务必须拆分为可独立验收阶段。每个阶段应有方案、实现、测试、审查、风险和完成标准，前一阶段未通过不得默认进入下一阶段。

### 文件拆分

- 过大页面组件按页面编排、数据加载、表单、图表、列表、状态展示和复用组件拆分。
- 组件同时负责请求、复杂转换、权限判断和多种展示模式时，应按变化原因拆分。
- 目录直接文件过多时按页面、组件、状态、请求、类型和样式分组；不为凑数量拆分只有一层转发的文件。
- 每次拆分后检查导入方向、循环依赖、公共接口、测试路径和页面行为是否保持一致。

### 配置、异常与安全

- 环境地址、功能开关、超时和第三方配置不能硬编码在组件中。
- 动态内容按上下文转义，富文本使用可信白名单；不得直接拼接不可信脚本、样式或地址。
- 检查令牌存储、跨站请求、开放重定向、敏感字段展示、第三方脚本权限和错误信息脱敏。
- 前端权限控制不能替代后端授权；隐藏按钮不等于接口安全。
- 复杂业务逻辑方法按仓库约定添加中文 Javadoc；关键处理步骤使用中文注释，简单展示和访问器不堆叠注释。

## 测试规范

按风险选择以下测试：

- 单元测试：格式化、校验、状态转换、权限判断和复杂业务函数。
- 组件测试：默认值、事件、表单、加载/空态/错误/无权限状态和可访问性。
- 接口模拟或契约测试：请求参数、响应类型、错误码、分页、超时和兼容字段。
- 浏览器端到端测试：关键用户路径、重复提交、刷新、返回、权限和异常恢复。
- 非功能测试：包体积、渲染性能、长列表、网络降级、浏览器和设备兼容。

测试失败必须先定位根因并修复，再重新运行直接相关测试；不得通过删除断言、跳过用例或降低验收标准掩盖失败。真实接口或生产环境验证必须获得单独授权。

测试记录至少包含实际命令、执行环境、输入或操作、页面/接口输出、数据状态、最终结论和未验证原因。

## 交付与运维

- 检查格式、类型、构建、组件测试、接口模拟、浏览器测试和产物大小。
- 确认环境配置、接口地址、缓存策略、静态资源版本和错误采集配置可区分。
- 发布前验证页面加载、核心路径、权限、错误状态、控制台异常和静态资源完整性。
- 需要用户可见变化时同步更新使用说明、接口说明、兼容矩阵或变更记录。
- 发现性能或功能回归时保留证据，按发布策略回滚前端产物或执行前向修复。
- 分支、工作树、合并请求和部署仅在仓库或用户要求时启用；目标分支和部署环境不明确时先确认。

## 典型问题和反模式

- 巨型页面组件同时承载请求、状态、转换、权限和全部展示逻辑。
- 全局状态存放临时页面状态，造成跨页面污染和难以测试。
- 只实现成功路径，缺少加载、空态、错误、无权限和重复提交处理。
- 仅通过隐藏页面元素实现权限控制。
- 直接使用不可信 HTML、脚本、地址或第三方资源。
- 为了所谓复用提前抽取复杂组件，导致参数爆炸和业务语义丢失。
- 只执行构建，不验证关键用户路径和错误恢复。

## 验收证据

检查：页面/组件/状态/请求目录、路由、接口类型、构建配置、静态检查配置、测试和错误采集配置。按项目支持的方式运行格式、类型、单元/组件、接口模拟、浏览器和构建命令；无法运行时记录原因。

交付记录应保留：变更文件、关键页面或接口、测试命令与结果、浏览器/设备范围、性能或包体积对比、发布方式、回滚方式和剩余风险。
