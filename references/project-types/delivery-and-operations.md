# 交付、部署和运维项目类型规则

## 适用条件

当项目包含构建、打包、容器、持续集成、发布、部署、环境管理、长期运行或运维自动化时启用。本文件可与任一项目类型规则组合；只做本地静态检查且没有交付行为的任务，按实际范围选择条目。

## 项目类型画像

实施或审查前记录：

- 入口：构建脚本、持续集成、容器文件、编排文件、部署脚本、配置和运行手册。
- 核心资产：源代码、锁定文件、构建制品、镜像、环境配置、迁移、发布记录、监控和备份。
- 主要依赖：代码托管、制品仓库、镜像仓库、云/服务器、数据库、密钥系统和监控平台。
- 关键风险：不可重复构建、秘密泄露、权限扩大、错误发布、数据迁移失败、无法回滚和不可恢复。
- 生命周期：开发、测试、预发布、生产、热修复、迁移、升级和退役。

## 需求与设计

### 目标与影响分析

- 明确发布对象、目标环境、变更范围、依赖、停机要求、兼容范围和验收标准。
- 明确配置、数据库模式、数据卷、网络、权限、资源、日志、指标、告警和回滚影响。
- 区分代码回滚、配置回滚、制品回滚、数据库前向修复和数据恢复；不能只写“重新部署旧版本”。
- 目标分支、部署目标、审批要求和观察窗口不明确时必须确认，不得按习惯猜测。

### 环境和制品边界

- 开发、测试、预发布和生产配置分离，环境差异显式化。
- 构建输入、依赖、基础镜像、版本、配置和制品应可追踪；生产不直接使用开发目录或未验证产物。
- 密钥由环境注入，不写入代码、镜像、日志、构建输出或示例文件。

## 实施规范

### 阶段化流程

1. 确认目标环境、发布对象、变更影响、验收标准和回滚条件。
2. 调研构建、持续集成、部署、配置、监控、备份和运行方式。
3. 设计制品、环境、权限、迁移、发布、观察和恢复方案。
4. 分阶段修改配置、脚本、容器或持续集成门禁。
5. 在隔离环境执行构建和部署验证，再进行授权范围内的目标环境验证。
6. 输出发布说明、门禁记录、运行手册、回滚方案和变更总结。

简单文档或非运行配置可以直接实施；涉及生产、权限、迁移、容器基础镜像、持续集成或发布链路时必须分阶段。每阶段具备方案、实现、测试、审查、风险和完成标准。

### 构建、依赖和持续集成

- 使用锁定文件和可追踪版本；依赖、基础镜像、插件和构建工具来源明确。
- 按提交、合并、发布和生产阶段配置格式、静态检查、类型检查、测试、密钥扫描、依赖检查、构建和迁移门禁。
- 失败门禁必须定位根因并修复；不得默认删除检查、使用 `--no-verify` 或忽略失败。
- 构建产物应包含版本、提交或其他可追踪标识，并能够复现或解释差异。

### 容器、进程和配置

- 涉及容器时，优先使用非 root、最小权限、最小基础镜像、固定或可审计版本、明确端口和资源限制；其他运行环境按平台能力落实等价的最小权限和版本可追踪要求。
- 健康/就绪检查与真实端口、路径、超时和启动参数一致；信号能够传递到主进程并支持优雅关闭。
- 配置通过环境或受控配置系统注入；检查默认值、必填项、敏感项和环境覆盖优先级。
- 数据卷、文件权限、临时目录、日志输出和构建上下文必须显式设计。

### Git、工作树和协作

- 高风险、多阶段或跨模块交付优先使用独立工作树，避免扰动用户当前工作区。
- 开始前记录当前分支、远端、工作区差异和用户已有修改；不回滚、不覆盖无关变更。
- 仅在仓库或用户要求时创建功能分支、合并请求或部署分支；不固定主分支名称和分支命名。
- 提交前检查变更范围、临时文件、调试代码、秘密、提交钩子和持续集成结果。
- 合并、同步主分支或切换最终制品后重新运行必要验证；发布成功后再清理临时工作树和过程分支。

## 测试规范

- 构建和制品测试：可重复构建、版本标识、依赖锁定和制品内容。
- 配置测试：必填项、默认值、环境覆盖、秘密注入和错误配置启动失败。
- 容器/进程测试：用户权限、端口、健康检查、就绪检查、信号和优雅关闭。
- 部署测试：隔离环境启动、核心接口/页面、任务、日志、指标、告警和数据状态。
- 恢复测试：版本回滚、配置回滚、迁移兼容、备份恢复和故障后重新启动。

默认执行本地和隔离环境验证。真实服务器、真实数据库、生产发布或真实回滚必须单独授权。记录命令、环境、制品/版本、输入、输出、数据状态、观察窗口、最终结论和未验证原因。

## 交付与运维

交付物按变更判断是否包含：构建说明、依赖清单、镜像说明、环境配置、迁移脚本、发布步骤、观察指标、告警规则、运行手册、备份恢复方案、回滚/前向修复说明和变更记录。

发布过程至少明确：负责人、审批、目标环境、版本、影响、发布步骤、健康检查、观察窗口、成功标准、失败处理、回滚条件和责任人。发布不能以“推送代码”结束；若要求合入主分支，应重新构建、部署和验证主分支产物。

## 典型问题和反模式

- 生产使用未锁定依赖或不可追踪构建产物。
- 秘密写入仓库、镜像、日志、构建参数或临时文件。
- 健康检查路径、端口或超时与实际服务不一致。
- 没有优雅关闭，任务或请求被直接中断。
- 只有代码回滚，没有配置、迁移、数据和制品兼容策略。
- 持续集成只执行构建，不执行测试、安全和依赖门禁。
- 在用户工作区直接切换分支、重置或清理文件。
- 主分支合入后继续使用个人分支产物作为最终发布物。
- 发布失败后提前删除分支、工作树或证据。

## 验收证据

检查持续集成配置、锁定文件、构建脚本、容器文件、编排文件、环境模板、部署脚本、发布记录、监控、告警、运行手册、备份和恢复记录。

保留构建命令、制品标识、目标环境、部署和验证命令、日志/指标、数据状态、观察窗口、回滚或恢复结果、审批和剩余风险。
