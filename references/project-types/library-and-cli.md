# 软件库和命令行项目类型规则

## 适用条件

当项目产出可复用库、软件开发工具包、命令行工具、插件、开发工具或发布给其他团队/用户使用的包时启用。本文件可与前端、后端、数据与模型、交付和运维规则组合；一次性内部脚本可按风险简化。

## 项目类型画像

实施或审查前记录：

- 入口：公共接口、导出模块、命令行入口、插件入口、配置和构建/发布脚本。
- 核心资产：公共类型、接口、错误模型、命令、包元数据、示例、文档和发布产物。
- 主要依赖：调用方、运行时、平台、操作系统、编程语言版本和第三方依赖。
- 关键风险：破坏兼容、资源泄漏、线程不安全、退出码错误、配置误读、供应链风险和不可回滚升级。
- 生命周期：开发、兼容维护、预发布、正式发布、弃用和退役。

## 需求与设计

### 公共契约

- 明确使用者、支持平台/版本、稳定接口、非目标能力和兼容承诺。
- 定义输入输出、错误类型、异常/退出码、资源生命周期、线程安全和并发约束。
- 对破坏性变更、弃用、默认值变化、序列化格式和配置优先级明确迁移方式。
- 公共接口只暴露稳定抽象；内部实现不应被调用方依赖。

### 模块边界

- 公共接口层负责稳定入口，核心逻辑保持可测试，平台适配和外部调用隔离。
- 命令解析、配置读取、业务处理、输出格式和退出码分离。
- 工具函数按稳定语义复用；不把无关能力堆到万能工具模块。

## 实施规范

### 阶段化流程

1. 确认公共契约、调用方、兼容范围和验收示例。
2. 调研已有接口、版本、文档、构建和发布方式。
3. 设计接口、错误、资源、线程安全、配置和迁移策略。
4. 分阶段实现，并同步更新测试、文档、示例和变更记录。
5. 验证安装、升级、卸载、兼容和发布产物。
6. 完成独立复审，确认没有意外扩大公共接口或破坏调用方。

简单内部实现可以直接修改；公共接口、序列化格式、依赖升级或破坏性变更必须分阶段，每阶段具备方案、实现、测试、审查、风险和完成标准。

### 版本与兼容

- 遵循仓库已有版本策略；没有约定时为公共行为建立可解释的版本和变更记录。
- 维护支持平台、运行时、依赖和接口兼容矩阵。
- 弃用先记录替代方案、过渡期、告警和移除条件；破坏性变更必须明确升级说明。
- 公共类型、方法、命令、配置和错误码的变更都要评估调用方影响。

### 资源和运行安全

- 明确连接、文件、线程、进程、临时目录、锁和缓存的创建、使用、关闭和异常清理。
- 检查线程安全、重入、并发、超时、取消和重复执行。
- 命令行参数和配置校验类型、范围、文件权限和敏感值；日志不得泄露秘密。
- 需要业务逻辑、流程控制或数据处理的方法，按仓库约定添加中文 Javadoc 和关键步骤注释。

## 测试规范

- 公共接口和错误模型测试：成功、失败、边界、空值、非法输入和兼容字段。
- 库测试：版本兼容、线程安全、资源释放、重复执行、取消和异常清理。
- 命令行测试：帮助、参数错误、配置优先级、标准输入输出、退出码、日志和机器可读模式。
- 安装/发布测试：安装、升级、卸载、不同运行时/平台、产物内容和依赖完整性。
- 集成测试：与代表性调用方、插件宿主或外部系统的契约和兼容验证。

默认使用模拟和隔离测试。真实调用方、真实发布仓库或生产工具链验证必须单独授权。测试失败必须定位、修复并重新验证；不得跳过直接相关失败项。记录命令、环境、输入、输出、版本、最终结论和未验证原因。

## 交付与运维

交付物按变更判断是否包含：公共接口文档、迁移指南、兼容矩阵、示例、变更日志、许可证、包元数据、构建说明、发布产物、校验和、回滚/降级说明和安全公告。

发布前检查包内容、版本、依赖、许可证、平台支持、文档、示例、安装/升级路径和弃用提示。发布后关注下载/调用错误、兼容反馈和安全问题；发现严重回归时保留旧版本并提供降级或修复版本。

## 典型问题和反模式

- 未经说明改变公共接口、默认值、序列化格式或退出码。
- 公共接口暴露内部实现，导致后续无法重构。
- 资源、线程、临时文件或子进程在异常路径泄漏。
- 命令行出错仍返回成功退出码，或把诊断信息写入机器输出。
- 没有帮助、示例、兼容矩阵、变更日志和弃用策略。
- 只在当前开发环境验证，不验证安装、升级、卸载和代表性调用方。
- 为了兼容保留无限期分支，缺少移除条件。

## 验收证据

检查公共导出、类型、命令入口、包元数据、构建脚本、测试、文档、示例、兼容矩阵、变更日志、许可证和发布配置。

保留测试命令、运行时/平台、输入输出、安装/升级/卸载结果、产物版本、兼容性结论、发布方式、降级方式和剩余风险。
